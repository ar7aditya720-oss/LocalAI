DESIGN DOCUMENTUI + System Architecture + Backend Integration DesignVersion 1.0 | September 2026

1. Document Purpose

This document defines the design of LocalAI, a self-hosted, on-premise agentic AI workbench for confidential organizational knowledge work. It combines the supplied web interface with a planned Python/FastAPI backend, local model runtime, agent orchestration, document processing, multimodal processing, local knowledge retrieval, sandboxed code execution, and deliverable generation.

The supplied UI is a single-page dark, animated workbench with a boot sequence, sidebar navigation, top status bar, chat workspace, command palette and animated local-AI visual core. fileciteturn2file0

2. Design Goals

Keep sensitive data and AI inference inside the organization's infrastructure.

Provide a modern local AI workspace while remaining self-hosted.

Start from a terminal command and expose the application through localhost.

Separate UI, API, agent, model runtime and tool layers.

Support multiple local models and task-based model routing.

Support multi-step agentic workflows.

Generate DOCX, XLSX, PPTX and verified code.

Make local execution, auditability and network state observable.

The agent must be tool-aware and must not receive unrestricted operating-system access. Each tool exposes a controlled interface and returns structured results.

11. Model Router

Task ↓Model Router ├── General reasoning model → documents / analysis ├── Coding model → code / debugging / tests └── Vision model → images / scanned documents / drawings

Ollama is the initial local model runtime, not the product identity. A model-adapter layer should allow another local runtime to be added later.

14. Code Execution Sandbox

Generated code should execute in an isolated sandbox rather than directly on the host. Docker is suitable for the prototype. The sandbox should enforce restricted filesystem access, timeouts, resource limits and controlled network access.

Coding request → Coding model → Generated code → Sandbox → Compile/Test → Verifier → Result

Design principle: the UI is the user's workspace; FastAPI is the local gateway; the agent is the execution layer; the model router selects local AI capabilities; tools perform controlled work; and the knowledge base grounds responses in organizational information.

25. Conclusion

The supplied interface is suitable as the presentation layer for LocalAI and already contains the main interaction surfaces required by the system. The next implementation step is therefore not a UI rewrite. The recommended approach is to preserve the current interface and replace its mock backend behavior with a real localhost FastAPI service. The system can then be expanded incrementally into model routing, agentic planning, PDF/OCR processing, local RAG, multimodal analysis, document generation, sandboxed coding and security/audit functionality.
